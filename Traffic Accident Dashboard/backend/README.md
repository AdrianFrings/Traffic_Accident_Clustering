# Backend API (Phase 2)

FastAPI + DuckDB service that serves the precomputed clustering results as JSON.
Replaces the per-request Nominatim geocoding and full-dataset loads that made the
Streamlit app slow. The heavy geo/ML stack stays in the offline processor; this
service only needs `fastapi`, `uvicorn`, and `duckdb` (no server/daemon — DuckDB
reads the Parquet files directly).

## Data prerequisites (Phase 1, offline)

Produced by the offline pipeline under `data/processed/`:

1. `clusters.parquet` — hotspot summaries (one row per cluster).
2. `points/City=<name>/*.parquet` — per-city points with WGS84 `Lat`/`Lon`,
   generated by `src/partition_points.py` (run once on existing data, or
   automatically as step 7 of `src/processor.py`).
3. `StreetName` column in `clusters.parquet` — baked in by
   `src/enrich_street_names.py` (resumable; the API falls back to `LocationName`
   for any cluster not yet enriched).

```bash
python src/partition_points.py        # build per-city point partitions
python src/enrich_street_names.py      # bake street names (resumable, ~1 req/s)
```

## Run the API

```bash
pip install -r backend/requirements.txt
uvicorn backend.main:app --host 0.0.0.0 --port 8800
```

`DATA_DIR` env var overrides the data location (defaults to `../data/processed`
relative to this folder).

## Endpoints

| Method | Path | Description |
| ------ | ---- | ----------- |
| GET | `/api/health` | Liveness check. |
| GET | `/api/cities` | All city names. |
| GET | `/api/cities/{city}/modes` | Transport modes available for a city. |
| GET | `/api/clusters?city=&mode=` | Hotspot summaries (worst-first). |
| GET | `/api/clusters/{id}/points?city=&mode=` | A cluster's points + nearby noise (lat/lon). |
